openagentix ist eine quelloffene, selbst gehostete **Agentenplattform**. Ereignisse kommen herein
(Webhook, Kafka, Cron, E-Mail; Chat über Webhooks), ein oder mehrere **Agenten** handeln über
**MCP-Tools und APIs**, jeder Schritt wird **vorab geprüft, protokolliert und mit Kosten erfasst**,
und die Ergebnisse gehen über die Tools, die ein Agent nutzen darf, hinaus, zum Beispiel als Pull
Request, Ticket-Update, Nachricht oder Bericht.

<Aside type="caution" title="Vorabversion">
  Version 0.1.0 ist als Tag `v0.1.0` gesetzt; ein GitHub-Release gibt es noch nicht, und das
  API-Container-Image ist noch nicht auf GHCR veröffentlicht, daher aus dem Quellcode mit Docker
  Compose bauen. `main` enthält schon mehr, das mit 0.2 erscheint: Mandanten, Modellschlüssel pro
  Geltungsbereich, Monatsbudgets, Air-Gap-Modus, typisierte Übergaben und `when`-Bedingungen,
  Tool-Profile, Agent Check und Agent Plan, das Claude-Code-Harness (mit echten Läufen verifiziert),
  einen OpenCode-Adapter (implementiert, Prüfung mit echtem Programm steht aus) und einen
  Kubernetes-Job-Runner als Baustein. Container-Runner und Credential-Broker sind noch in Prüfung.
  Die Seiten kennzeichnen, was **verfügbar** ist, was im **nächsten Release** kommt und was auf der
  **Roadmap** steht.
</Aside>

agentix-zero ist das Agenten-Konto des Projekts und schreibt den Großteil von Code, Tests und Doku.
Menschen prüfen jede Änderung und tragen die Entscheidungen; die Projektleitung ist der Maintainer.

Vom Homelab bis zum Unternehmen: Eine Person auf einem einzelnen Server kann alle Rollen
innehaben. Ein Unternehmen ergänzt Mandanten, Zugriff pro Agent, Single Sign-on und signierte
Audit-Checkpoints. Kern, Gate und Audit-Trail bleiben gleich.

## Die Ideen in einer Minute

- **Ereignisse starten Läufe:** Ein signierter Webhook, eine Kafka-Nachricht, ein Zeitplan oder
  eine E-Mail erzeugt ein Ereignis; jedes Ereignis startet einen Lauf.
- **Prüfung vor jedem Tool:** Das Audit-Gate jedes Agenten prüft Tool-Aufrufe vor der Ausführung
  gegen Allowlist und Argumentregeln – mit deterministischem Code, nicht mit einem Modell.
- **Ein Kontroll-Agent wacht:** Budgets, Raten, Datenklassen und verbotene Aktionen gelten für alle
  Läufe; Läufe können angehalten oder beendet werden.
- **Alles im Protokoll:** Jeder Schritt landet in einem nur anhängbaren, per SHA-256 verketteten
  Audit-Trail mit signierten Checkpoints – und trägt seine Kosten.
