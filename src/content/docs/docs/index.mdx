> **open-agentix – the agentic platform.** Built by agentix-zero, an AI agent. That is how much we
> trust our goal and vision.

openagentix is an open-source, self-hostable **agent platform**. Events come in (webhook, Kafka,
cron, e-mail; chat through webhooks), one or more **agents** act on them through **MCP tools and
APIs**, every step is **policy-checked, audited and cost-tracked**, and results go out through the
tools an agent is granted, for example as pull requests, ticket updates, messages or reports.

<Aside type="caution" title="Pre-release">
  Version 0.1.0 is tagged (`v0.1.0`); there is no GitHub release yet, and the API container image
  is not yet published on GHCR, so build from source with Docker Compose. `main` already contains
  more, which ships in 0.2: tenants, model keys per scope, monthly budgets, air-gapped mode,
  typed handovers and `when` conditions, tool profiles, Agent Check and Agent Plan, the Claude
  Code harness (verified with real runs), an OpenCode adapter (implemented, real-run verification
  pending) and a Kubernetes Job runner as a building block. The container runner and credential
  broker are still in review. Pages mark what is **available**, what is **in the next release**
  and what is on the **roadmap**. Names of settings may still change before 1.0.
</Aside>

<Aside type="note" title="Who writes this project">
  agentix-zero is the project's agent account. It writes most of the code, tests and these docs.
  Humans review every change and own the decisions; the project lead is the maintainer.
</Aside>

<Aside type="tip" title="From homelab to enterprise">
  One person on a single server can hold every role. A company adds tenants, per-agent access,
  single sign-on and signed audit checkpoints. The core, the gate and the audit trail stay the same.
</Aside>

## The ideas in one minute

<CardGrid>
  <Card title="Events start runs" icon="rocket">
    A signed webhook, a Kafka message, a cron schedule or an e-mail creates an event. Each event
    starts one run of an agent or a pipeline of agents.
  </Card>
  <Card title="Gates before tools" icon="approve-check">
    Every tool call is checked by the agent's audit gate before it executes: allowlist and argument
    rules, evaluated by deterministic code.
  </Card>
  <Card title="A control agent watches" icon="magnifier">
    Budgets, rates, data classes and forbidden actions apply across all runs. Runs can be paused or
    stopped.
  </Card>
  <Card title="Everything on the record" icon="document">
    Steps land in an append-only, SHA-256 hash-chained audit trail with signed checkpoints, and
    every step carries its cost.
  </Card>
</CardGrid>
